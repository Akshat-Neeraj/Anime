**Previous session (rate-limit error still leaking through — 429-only check wasn't enough)**
- 🔴 Fixed: **the previous session's chat-retry fix didn't catch every rate-limit shape.** User's first real chat message failed immediately with the raw provider text ("Sorry, I ran into an error: Rate limit reached for model `openai/gpt-oss-120b` ... tokens per minute (TPM): Limit 8000, Used 1696, Requested 6365...") — no retry toast, no backoff. Root cause: Groq's TPM-exceeded error doesn't always come back as HTTP 429; it can arrive as a 400 `invalid_request_error` whose *message* says "Rate limit reached ... tokens per minute", and the retry loops in `callAI()`, `callAICompound()`, and `sendChat()` all gated retry strictly on `res.status===429`, so that shape slipped straight through to the user with zero retries.
- 🔧 Added `isRateLimitResponse(status, data)` — treats a response as retryable if `status===429` OR the error message matches `/rate.?limit/i`, `/tokens per minute/i`, or `\bTPM\b`, regardless of HTTP status. All three retry loops now use it.
- 🔧 Added `extractRetryDelayMs(message)` — parses Groq's own "...try again in 457.5ms" / "...try again in 2.3s" hint out of the error text so a retry waits the *actual* suggested time instead of blindly waiting the fixed 3s/8s schedule (falls back to that schedule when no hint is present).
- Test `t-ratelimitshape` added — mocks `fetch` to return a 400 with a TPM-style `error.message` once, then succeed; confirms `sendChat()` retries automatically and the delay-parser reads "457.5ms" correctly. Existing `t-chatretry` (plain-429 case) still passes unchanged.
- Root cause is unfixed *risk*, not just the symptom: this account's Groq tier is genuinely a tiny 8000 TPM budget, and even a "trimmed" chat prompt (library snapshot + recent history) can occasionally still bump into it on a long session. The retry logic now means a single stray rate-limit response no longer surfaces as a hard error — it silently retries and (per Groq's own suggested wait, usually well under a second for this class of error) almost always succeeds on the next attempt.

## What this is
A single-file HTML personal media tracker hosted on GitHub Pages, covering anime, manga, manhwa, manhua, doujin, movies, TV, K-drama, JAV, hentai, games, and 20+ other types. AI-powered via Groq. Cloud sync via Supabase. Zero build step, zero dependencies beyond CDN-free vanilla JS.

## Architecture
- **File:** `nightlist_upgraded.html` — one file, HTML/CSS/JS all inline, ~5,700 lines
- **Hosting:** GitHub Pages (static)
- **AI:** Groq API (`openai/gpt-oss-120b` for text, `qwen/qwen3.6-27b` — preview, vision-capable — only when an image is attached in chat). `groq/compound` (with built-in web search) used specifically for the "Where to Watch" feature so it gets live results instead of stale training data.
- **Cover art sources:** Jikan (MAL) → AniList (GraphQL, no key) → TMDB (movies/TV, needs a key — shared fallback key embedded, but rate-limit/revocation risk since every copy of this file shares it; users can set their own via sidebar → TMDB Key) → iTunes Search API (music/MV only)
- **Related media / recommendations:** AniList's `relations` and `recommendations` GraphQL fields
- **Airing schedule:** AniList's `nextAiringEpisode` field, cached 6hrs client-side
- **Sync:** Supabase, single `nightlist_sync` key-value table. Syncs library, lists, covers, AND chat sessions
- **Storage:** localStorage as source of truth; Supabase is the cross-device sync layer on top

## Known bugs — fixed
- **AI Fill silently discarded the corrected title**: `autoFill()` already asked the AI to find/correct the official title (using the selected type to disambiguate same-name adaptations like Solo Leveling anime vs manhwa) and used that corrected title internally for cover-art and related-media lookups — but a `// Title never overwritten by AI fill` line meant the visible Title field was never updated with it. So typing "solo lvling" would correctly fetch the right cover/synopsis/tags, but the saved entry kept the typo. Fixed: Title field now updates to the AI's corrected title, with a toast confirming the change so it's transparent rather than a silent overwrite. Also strengthened the Fill prompt to explicitly handle the same-title-multiple-adaptations case and known abbreviations (AOT, SxF, OPM, etc.). Test `t-filltitle` mocks `callAI` to verify this offline, without needing live network access.
- **Achievements adult-content leak**: the last residual from the Stats/Wrapped/Tier List audit — all 16 achievement `check()` functions read raw `LIB`, so a hidden adult title could shift a milestone count by 1 while locked (Tier Master was also counting tier-placed IDs regardless of visibility). Added `eligibleLib()` helper and rewrote every check to use it.
- **App-breaking TDZ (temporal dead zone) crash on load**: boot sequence called `loadTrash()` before `let TRASH = []` had executed (declared ~230 lines later in the file), throwing `ReferenceError: can't access lexical declaration 'TRASH' before initialization` and halting the entire app before it could render anything. A second, identical instance (`REVEALED_ADULT_COVERS`, read by `cardG()` inside the boot sequence's `renderLib()` call) was masked by the first crash and only surfaced once TRASH was fixed. Fixed by moving the bare `let` declarations up near other early global state, ahead of the boot sequence — functions that use them were left in place, since function declarations (unlike `let`/`const`) are fully hoisted and don't have this problem. This class of bug is invisible to syntax checking (`node --check`/`new Function()`) since the code is syntactically valid; it only fails at runtime, in execution order. Added a `jsdom`-based boot test to the validation process specifically to catch this going forward — see "Current state" below.
- Tag palette (`TAGS` array in Add/Edit) had isekai/harem/webnovel-trope tags and mature/explicit descriptors ordered before general genre tags like "comedy" or "sports," so a normal title's relevant tags were buried below the fold. Reordered general → niche → romance framing → mature/explicit → archetypes. Also made `renderFTags()` sort selected tags to the front so AI Fill's picks are visible without scrolling.
- **Detail-view rating desync**: clicking a star to rate, then moving the mouse off the widget, could visually snap back to a stale old rating. Root cause: the `onmouseout` handler's "revert to this value" argument was baked into the HTML string at initial render time (`x.rating` at render), not read live — so after `detSetRating()` updated the actual data, the DOM's `onmouseout` attribute still pointed at the pre-click value. There was also a related duplicate-text bug: clicking a star on an already-rated entry (which had a separate static "/10" span from the initial render) could produce "8 / 10/10". Fixed by removing the hover-preview mechanism entirely — rating is now click-only (matches user preference that hover shouldn't change the display), reading/writing a single consistent DOM node, with a plain CSS `:hover` color cue instead of a JS-driven cascade preview.
- **Adult-content leaks in Stats/Wrapped/Tier List**: these three views iterated the raw `LIB` array directly, with no check against the PIN lock — so even while "Adult Content" was set to HIDDEN, a flagged/adult-type entry's title could appear in Wrapped's "highest rated" card, its tags/type/rating could inflate Stats breakdowns, and an already-tiered adult card would still render on the Tier List board. Fixed by filtering all raw-`LIB` reads in `renderStats`, `calcWatchTime`, `buildHeatmap`, `buildScoreChart`, `buildGenreBreakdown`, `buildTypeBreakdown`, `renderWrapped`, and `renderTierList`'s `mkCardEl` to respect `SHOW_ADULT`, exactly like the Library view already did. `shareWrapped()` (external share) always excludes adult content regardless of lock state, same rule as the Share List fix.
- Sidebar and category-tab scrollbars rendered thick/gray/native-looking on mobile despite `::-webkit-scrollbar{width:4px}` being set. Root cause: newer Chromium-based mobile browsers prioritize the standardized `scrollbar-width`/`scrollbar-color` properties over the legacy `::-webkit-scrollbar` pseudo-element — since only the webkit version was set, those browsers fell back to the thick default. Fixed by adding `scrollbar-width:thin;scrollbar-color:var(--bg5) transparent` universally. Note: some Android WebViews show a native OS-level scroll-overlay indicator only *during* active touch-scrolling that no CSS can override — if it's still big only mid-scroll (not at rest), that's the OS, not the page.
- `HARDCODED_KEY` was left as literal placeholder text, which is truthy, so it silently overrode any real Groq key the user saved in Settings → all AI calls failed. Fixed: empty by default, falls back to Settings key properly.
- Chat sessions were built (data model + functions) but the UI strip to switch sessions was never added to the DOM, and messages saved to a disconnected legacy `nl_chat` key. Fixed: UI wired up, storage consolidated, legacy data migrated on first load.
- `clearFilters()` was defined twice — JS silently used the second (incomplete) definition, so filters never fully reset. Merged into one correct version.
- Music/MV covers were routed through TMDB (no music catalog). Switched to iTunes Search API.
- `llama-3.3-70b-versatile` was deprecated by Groq (shutdown 08/16/26). Migrated to `openai/gpt-oss-120b`.
- Briefly used `qwen/qwen3.6-27b` (a **preview** model) as the *default* model, which broke Fill entirely. Fixed: preview model now only used for the vision/image-attachment case.
- AI's raw `<think>` reasoning was leaking into visible chat output, including a case where it fabricated fake biographical info about a real-sounding person. Fixed: strip `<think>` tags from all AI output, and rewrote the system prompt to require honesty over confident-sounding fabrication.
- "Where to Watch" prompt had dead site names hardcoded as examples, directly causing the AI to suggest them. Switched to `groq/compound` with real web search.
- Chat markdown wasn't rendered — raw `**`/`#`/`|table|` shown as literal text. Added a lightweight markdown-to-HTML renderer, plus horizontal scroll + 4-column cap + a system-prompt nudge toward lists over tables for the narrow chat panel.
- Duplicate detection was title-only, ignoring type — blocked adding "Solo Leveling" (anime) because "Solo Leveling" (manhwa) already existed. Fixed in `qadd()`, `quickAddRelated()`, and the live in-form warning (`checkDuplicate()`), all now type-aware, with visual distinction between a true duplicate (red) and a same-title-different-type entry (amber, informational).
- Sequential "Finding cover art…" / "Cover found!" toasts stacked visually on fast resolves. Added toast key-based updating so related toasts merge instead of stacking.
- Game covers ("God of War" etc.) always failed — TMDB has zero game data, so games silently fell through to a TV search that could never match. Added a proper RAWG-based path (optional personal key, same pattern as TMDB).
- Accidentally deleted a function's signature line while inserting new code above it — happened **five** separate times across this project (`anilistCover`, `epInc`, `handleLetterboxdImport` ×2, `loadAiringBadges`). Caught every time by the mandatory `new Function()` + `node --check` validation step after each edit.
